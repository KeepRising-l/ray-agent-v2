# R06 三模式验收

2026-10-30。本节由助手协作实现，用户尚未阅读新增源码；验证通过不等于用户已掌握。

## 固定边界

| 会话模式 | 资料范围 | 执行路径 | 失败行为 |
| --- | --- | --- | --- |
| CHAT | 不接收知识库 | GeneralChatWorkflow → 网页 Agent，普通问题直接回答 | 工具失败如实展示，不声称联网成功 |
| KNOWLEDGE | 创建时选择1～5个自己的知识库 | 固定检索、证据判断、引用生成 | 无依据固定拒答，不转联网 |
| AUTO | 创建时可选0～5个自己的知识库 | 规则/结构化分类 → DIRECT、KNOWLEDGE、WEB、HYBRID、CLARIFY | 非法分类或分类失败先澄清；无资料范围不能读库 |

会话模式和范围固定，改变页面“新会话模式”不会修改已有会话。当前服务端身份仍为 local-owner，登录未实现，不宣称支持多人认证。

AUTO 的分类、子工作流共享模型总次数和总时限；工具预算沿用运行配置。DIRECT不提供网页定义；KNOWLEDGE不提供任何工具。WEB必须有实际工具尝试，模型跳过工具却声称已搜索会失败；工具预算为0时固定说明未联网。明确的“不要联网”“不要读取知识库”先由代码规则收窄路径。规则是有限意图基线，不能宣称覆盖所有自然语言表达。

HYBRID先查询所选授权资料，再最多搜索一次、抓取首个结果一次，工具数为0/1时相应收缩。搜索只使用本次用户问题的有限长度片段，不发送检索正文或历史。最终模型返回知识库、网页、比较三个栏目，代码检查字段与K/W来源后才发布文本；所以混合回答会先显示轨迹，正文在校验完成后出现。资料缺失、检索失败或网页失败分别说明，两类证据不齐时不生成可靠对照结论。冲突由模型并列说明与标注，编号校验不等于语义冲突已经被自动证明。

## 执行方法

先执行 `mvn -B package`，待结束后再运行脚本；Windows 不要覆盖运行中的jar。

- `python tools/verify_r06.py --browser`：模拟模型/Embedding、禁用Tavily、真实PostgreSQL，验证模式、路由、网页失败降级和页面。
- `python tools/verify_r06.py --live --browser`：使用受忽略本机配置里的真实模型、Embedding、Tavily；会消耗实际接口用量。
- `mvn test`、前端 `npm test` / `npm run build`：常规构建与测试；真实数据库/外部接口默认跳过。
- 真实PG JUnit另启用 `RAY_PG_TEST=true` 及 `RAY_TEST_DB_URL/USER/PASSWORD`，覆盖会话范围持久化、跨owner拒绝、文档和向量事务。

脚本读 `tests/fixtures/mode-boundary-cases.json`，13个样例分别核对目标及检索/工具是否实际发生；另验证非法模式与范围。测试schema和文件目录使用随机名称并清理，报告写入忽略的 `logs/r06-mock.json` / `logs/r06-live.json`；浏览器截图 `logs/r06-browser.png`。不把模拟结果当真实模型效果，不把这13题当通用路由准确率。

## 验收观察点

1. CHAT询问私有代号不能读出资料；KNOWLEDGE被要求联网时仍只检索，空库拒答。
2. AUTO问候不检索、不执行工具；资料问题带K引用；无资料范围先澄清。
3. AUTO新信息请求有网页工具轨迹；混合回答同时出现K/W来源，分别能打开原文/网页链接。
4. 未选择或空知识库、网页失败分别说明，不能以另一类来源冒充缺失类别。
5. 刷新后路由、来源、工具卡恢复，切“新会话模式”后仍须新建才能改变会话模式。
6. 单测注入非法/重复/额外JSON字段、模型分类失败、虚构与串用K/W引用、资料删除、证据冲突、0/1工具预算、取消和超时。

真实网页可能拒绝抓取。本次验证曾观察到HTTP403，搜索摘要仍可用；页面保留失败工具卡，回答说明无法依据该正文核实。它不是抓取成功的证据。

尚未实现：登录、AUTO复杂问题拆解/重写、通用澄清挂起接续、摘要压缩、多Agent、混合召回/重排、部署与容量验收。
