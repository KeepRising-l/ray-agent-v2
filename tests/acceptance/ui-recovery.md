# R09 工作区与异常恢复验收

2026-10-31。实现验收基于双远程main的3d76bb8，R09由助手协作完成；提交与推送状态以Git历史和双远程为准。用户未阅读R09新增源码，理解待确认。设计与取舍见[工作区设计](../../docs/r09-workspace-design.md)。

## R09-01 会话、模式与资料

App负责页签，ChatWorkspace负责视图，`stores/chatSession.js`负责会话状态、操作及异步保护。沿用项目JavaScript/Vue，未为计划中的.ts文件引入TypeScript或Pinia。SessionList、ModeBadge展示服务端数据；创建模式与当前会话明确分开。

切换先清除旧正文、轨迹和问题，再按选择序号接收响应；旧响应丢弃。本页每个会话独立持有自己的SSE操作和草稿，切到别的会话不会接收前一会话的流。运行结束后再次读取持久记录，保留所选历史run；不会把轮询返回的最新run强行覆盖用户选中的旧run。

## R09-02 文档与可定位引用

原KnowledgePanel的实际逻辑迁入KnowledgeWorkspace，DocumentStatusList明确区分处理进度与已有有效版本。失败的新版本可以与上一有效版本同时存在，处理失败不会把旧有效版本说成失效。处理尝试可展开；当前页持续查询，能看到后台自动重试后就绪。

SourcePreview显示文档版本、页码/段落和服务端重新校验的原文；来源在更新或删除后显示失效。MessageContent让每条历史回答的K/W标记绑定其runId，切到新回答后仍可从旧正文找回旧来源。未记录的引用只显示无记录提示，不伪造原文。输出期间锁定引用切换，避免当前流与历史轨迹混用。

## R09-03 运行过程与用户补充

复用PendingQuestionPanel承担课卡QuestionCard职责，避免新建同功能空组件；回答提交原runId/questionId，失败时保留补充输入。RunEventTimeline按seq去重排序，显示摘要/路由/工具/排队与终态事件，不显示原始JSON堆栈。ContextUsageView区分估算、供应商usage和含排队/等待的总耗时，未知usage不按0补齐。

当前没有SSE断点续传。刷新后重新查询历史、事件与待答问题；有效WAITING_USER可接续，已经中断的运行不自动重放。

## R09-04 取消与重试范围

RunActions与RunErrorNotice提供停止、刷新/查询原请求和编辑后重新提问。已有run的响应不明时先查该请求；查到原run不重新执行。尚无run编号且网络结果未知时，保留原clientRequestId与消息，刷新浏览器也可查回；未查询前禁止盲目发送，404后的相同输入重发仍使用原编号。

已失败的模型运行只能明确编辑后重新发问；编辑本身不发网络请求，新的发送使用新编号。文档重试保持原最新文档版本，不触发整轮聊天重跑。任务页取消/重试按钮在操作期间禁用，失败不伪造终态。运行态集中在chatSession.js，不另造平行runState存储。
