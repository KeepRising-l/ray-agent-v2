# R11 质量、容量与交付记录

2026-11-01，开发基于main的fb48f88。R11由助手协作实现，用户本轮尚未阅读新增源码，理解待确认。本轮提交/推送状态以Git及统一规划为准。

## 环境与验证范围

宿主Windows 11、i5-13500HX（14核/20逻辑处理器）、约15.7 GiB内存；Oracle JDK17.0.12、Maven3.9.9、Node24.19.0。Spring Boot4.1.2；WSL Docker29.7.2 / Compose5.5.0，PostgreSQL16.15、pgvector0.8.6。模型为本机配置的兼容接口，名称不证明独立上游身份；Embedding真实使用BAAI/bge-m3 / 1024维。

本机同时有镜像拉取及开发进程，部分模拟回归也并行运行；不是专用性能环境。所有资料均为自写，集成脚本创建并清理自己的schema、存储与进程，不改用户已有会话或全局Docker配置。

## 真实检索效果

[固定检索对照](retrieval-comparison.md)中，16条相近规则加4条语义表达，向量@3为17/20、@6为19/20，RRF两者均为20/20；@6改善第4题，本集合未观察到退化。4条指代样例向量@6由1/4变为4/4。平均向量SQL约42.95 ms，融合SQL及本地处理约89.39 ms，完整含Embedding查询约257.99 ms。

当前模型重排只在一个有候选的业务样例验证成功接线、编号约束和计量，未测得足够的独立排序质量收益。三个实验开关仍默认关闭；没有自动修改用户当前配置或旧索引。

## 隔离容量观测

`tests/load/run-capacity.js`经R11夹具启动：24个独立会话请求、12个并发发送者，设置1个运行槽、2格排队，模拟模型固定等待150 ms。实际接受3、拒绝429为21，观测最大准入3，拒绝请求没有创建run，最后容量归零。

本轮样本接受请求加后续状态/容量核对的P50约686.71 ms、P95约905.32 ms，总过程约906.48 ms。接受样本只有3个，不能用它估算稳定延迟、默认2/8配置的容量或真实模型QPS；没有用拒绝请求拉高“成功吞吐”。原始记录在受忽略的`logs/r11/capacity.json`。

## 干净环境交付

Docker实际从源码构建，未使用宿主target、node_modules、模型配置或用户数据库卷。基础镜像按本次实际解析摘要固定，依赖缓存只用于后续提速。`python tools/verify_clean_start.py`使用随机Compose项目和全新卷，验证欢迎页及JS/CSS、个人登录、后台和移动宽度；停止的只是本测试项目数据库，健康503后重连恢复，应用重启后账号与资料均保留。结束时只删除本测试项目容器、网络和卷。

结果在受忽略的`logs/r11/clean-start.json`、`clean-compose.log`与`clean-start-browser.png`，源码镜像构建日志在`docker-build.log`。当前是本机Docker验证，不代表公开服务器、TLS或容器网络内外部供应商均已验证。正常IDEA运行仍使用前后端开发服务，不强制切换容器。

开发验收收尾时扫描297个Git可见源码/文档文件及统一规划目录，对照本机真实密钥和私钥格式，无凭据候选命中；根目录和deploy下的私密配置均受忽略。随机测试项目的容器与数据卷已核验清理。`git diff --check`通过，统一规划49课卡/553链接无失效，旧工程HEAD及规划外状态不变。当时尚未暂存、提交或推送；后续提交状态见Git及统一进度表，用户阅读与理解保持待完成。

## 失败与修正

- 首次R11模拟业务补充问题失败：模拟回答器只查当前问题的编号，未正确处理“它”所对应的已校验证据；修正模拟响应构造后通过。未把模拟协议错误冒充真实RAG缺陷。
- 旧R05浏览器在Vite未就绪时登录而ECONNREFUSED：公共验收登录助手改为等待实际会话端点就绪，最终浏览器连续3轮通过。只重试读取，不重放认证或业务写操作。
- R05原始HTTP取消检查没有携带Cookie/CSRF，表现为收不到run元数据；已补齐同一已登录会话的请求头。前20问当时已通过，取消分支单独修复复验。
- 发布构建明确将Vite资源放到classpath `/static`；生成文件在target，不写回源码。Docker上下文排除本机密钥、身份、原文、Git、日志与构建缓存，基础镜像按实际摘要固定。
