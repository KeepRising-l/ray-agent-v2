## 本轮采纳的修订

1. **迁移回填顺序**：`queue_seq` 历史数据使用 `row_number() over (order by created_at, id)` 确定顺序，再推进序列；新数据统一走数据库默认 `nextval`，避免依赖 UPDATE 顺序或 INSERT 双重取号。
2. **排队位置语义**：位置统计当前 run 前面的全部活动状态，不只统计 `QUEUED`。位置与阻塞原因分开表达，`blockedBy` 由调度器给出，支持区分运行中、等待用户补充和全局槽位不足。
3. **资源释放统一化**：终态提交成功后，统一按“释放 session gate → 清理全局 permit/running 占位 → 唤醒队列”执行。数据库终态提交失败时不提前开放会话。
4. **异常路径补齐**：除 `states.start()` 失败、permit 关闭后 job 跳过外，增加 `workers.execute(job)` 被拒绝的清理与终态处理要求。
5. **过期检查点**：过期扫描返回过期 run；所有调用点（包括 `consume()` 内部）都必须把结果交给协调器，禁止保留只改数据库状态、不释放 gate 的副作用调用。
6. **超时单一化**：以 `session-queue-timeout-ms` 作为准入到开始执行的唯一排队上限；`queue-timeout-ms` 停用，避免两个等待 deadline 竞争。排队等待和实际运行预算各自计时；续跑仍扣除同一 run 已消耗的活跃时间。
7. **前端消息关联**：乐观消息用 `clientRequestId` 关联，收到 `meta` 后补 `runId`；刷新时按 run 合并，避免多条并行 SSE 时错绑消息、取消按钮或回答。
8. **多流状态隔离**：明确 `refresh()`、`active`、`currentRun`、恢复 pending 均需按当前运行/请求归属，避免排队流覆盖正在运行的流。
9. **失败轮次上下文**：本期维持当前行为，失败/取消/超时消息不进入模型历史；用户消息仍保留在界面和数据库，并提示上一条未完成。改变这项产品语义另行评审。
10. **实施前置**：主文档已记录两个独立提交作为完成的前置，不再要求把重构与排队功能混在一起提交。

## 保留为实施阻塞项

### 浏览器连接数

原文“每会话最多两条 SSE 可以保护浏览器连接数”的论证不成立：HTTP/1.1 同源连接数按浏览器 origin 计算，不按会话计算。多个会话或标签页的 SSE 总数仍可能达到全局运行准入上限，并阻塞同源 API 请求。

主文档已将其改为实施阻塞决策：实施前必须选择并验证 HTTP/2、将运行提交与事件订阅拆分，或设计可复用的单 SSE 协议。每会话上限 2 只能限制单会话资源，不能替代全局连接治理。
