# R10 个人登录与统一管理后台

2026-11-01。沿用R10-01～R10-04，补齐前置R00-03。由助手协作实现，用户本轮未开始阅读新增源码；实现、验证与理解分别记在统一规划目录。

## 用一条请求理解职责

用户登录后修改默认模型，再发送“你好”：浏览器先取得登录状态与CSRF令牌，Spring Security验证会话；后台保存非秘密模型配置、版本与操作者，密钥单独落到本机忽略文件。聊天请求在入队前选择当前模型及策略，把配置快照与run放进同一个数据库事务。后续执行使用已捕获的适配器，后台再改配置也不会改变这个运行。

登录保护覆盖聊天、资料、任务和后台API，不只是隐藏一个菜单。采用Boot 4.1.2管理的Spring Security 7.1.2，会话认证、登录时更换会话ID、CSRF、退出失效使用框架机制。没有JWT、自建密码算法、注册和多角色管理。首次启动生成随机密码，账号文件保存BCrypt散列；初始明文另写本机文件，不写日志或接口。

登录账号与数据owner职责不同：当前唯一账号拥有角色OWNER，服务端继续绑定既有`local-owner`，保留R01～R09的数据。前端传ownerId不能改变归属；异步任务同样使用服务端owner，不能依赖HTTP线程的登录上下文。此实现没有提供多用户隔离验收。

## 模型配置与运行快照

- `AdminSettingsStore`：数据库保存配置、revision和审计；更新比较revision，过期页面返回409。共同短锁协调新run入队、文档领取与向量配置切换。
- `ModelSettingsService`：管理聊天渠道与独立Embedding配置；本机环境只作为尚无数据库配置时的初值。密钥留空保留、明确清空才删除引用，API只返回是否配置。
- `ModelChannelService`：配置变更安装新适配器，已入队或执行中的运行保留原实例。旧版本适配器到进程关闭时统一释放；首版个人规模采用这个简单方案，没有实现引用计数回收。
- `RunSnapshotService`：与run原子保存渠道、模型、地址、模型版本、策略和Embedding标识，不保存密钥。等待用户补充后沿用原预算和策略；当前模型版本不同则拒绝消费问题，用户可取消后重问。

R10之前没有快照的历史运行可以查看原运行事件，但不凭当前配置补造历史快照。旧WAITING_USER若缺少可验证快照，需要取消后重问。

Embedding切换要求没有排队、运行、等待补充以及文档处理中任务；额外跟踪已领取但可能被删除的文档，避免旧空间任务正在执行时切换。接口地址、模型、维度及版本共同决定向量空间。旧索引继续保留，但不会参与新空间检索；页面提示需要明确重建。重试沿用版本绑定的目标空间，重建才创建绑定当前空间的新版本。

数据库、密钥文件与运行中客户端不是跨介质事务：先写本机密钥再保存配置，失败可能留下未使用的密钥引用，不会把密钥写进数据库。当前本机密钥文件未加密；备份应包括数据库、身份文件、密钥与原文。

## 补偿边界与观察口径

后台复用知识库工作区和任务面板，不另造空的KnowledgeAdminService、Tasks.vue或KnowledgeBases.vue。运行只提供取消；文档提供重试、重建和删除。动作先持久声明requestId，重复请求返回同一审计记录；目标不符返回409，按钮等待期间禁用。REQUESTED表示尚未确认，进程重启将其标记INTERRUPTED，不自动重放外部调用。没有承诺外部副作用exactly-once。

文档版本、失败码、处理尝试、操作者及补偿结果可相互定位。普通工作区已有接口继续使用；后台审计的范围是后台配置、探测和补偿，不声称覆盖所有业务读写。

工具策略只控制既有网页搜索、抓取、AUTO、模型分类及运行预算，新运行取快照。CHAT不获得检索能力，KNOWLEDGE仍固定RAG且不转联网，AUTO仍由代码校验目标与授权范围；开关不能注册任意插件或外部命令。队列容量、线程数等仍由启动配置控制，没有伪装成热更新。

统计按当前owner和run创建时间窗口查询数据库，不用最近100条列表推算总量。已知token求和，缺失usage另计且不补0；总耗时包含排队和等待。TOOL_STARTED计尝试，TOOL_SUCCEEDED计成功返回。会话/审计列表最多100条与完整统计是不同口径。

## 前端与阅读入口

保留现有Vue/JavaScript和白底系统控件。`AuthGate`负责登录、失效和退出后销毁私有工作区；`AdminLayout`组织概览、模型、向量、知识库、任务、策略、运行与操作记录。没有为课卡拟定的.ts路径引入TypeScript或路由库。

登录/退出与写请求自动带CSRF；认证失效显示登录，不能自动重放原来的写操作。模型/策略保存有明确反馈，密钥从不回填；运行观察切换采用选择序号，丢弃迟到的旧快照。

建议后续带读顺序：`SecurityConfiguration`与`AuthGate` → `ModelSettingsService`与`RunSnapshotService` → `TaskAdminService`与`AdminOperationService` → `RuntimePolicyService`与`RunStatisticsService`。本轮没有要求用户逐类考试，也没有把测试通过记录为掌握。

框架机制参考[Spring Security官方CSRF文档](https://github.com/spring-projects/spring-security/blob/7.1.1/docs/modules/ROOT/pages/servlet/exploits/csrf.adoc)，编译与运行版本以本项目Boot依赖管理实际解析结果为准。运行验证见[后台验收](../tests/acceptance/admin-console.md)。
