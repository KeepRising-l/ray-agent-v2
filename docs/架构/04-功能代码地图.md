# RayAgent V2 功能代码地图

这份地图回答“我要找某个功能，应当先打开什么代码”。范围是当前 `ray-agent-v2` 工作区生产代码，基于 2026-11-04 的 `Ray/structure-context-rag` 工作区整理，起点 `4d1c114`；运行准入类已移至 `run.admission`；旧版 `ray-agent` 是另一个工程，不能用这份地图判断旧版行为。代码后续变动时以实际源码为准。

**怎么看：**先按功能找到入口，再沿“主要经过”阅读；“修改时找哪里”和“已有测试”用于定位，不代表改动后可以跳过验证。箭头表示主要执行阶段；涉及接口、异步调度和流式订阅时，不等于前一个方法直接同步调用下一个方法。测试链接只说明测试存在，本次整理未运行测试。部分 PostgreSQL 或外部服务测试需显式配置才能执行。

## 01 发送聊天消息

**入口：** [ChatWorkspace.vue](../../ray-agent-web/src/pages/ChatWorkspace.vue) 提供输入框和发送按钮；前端状态与发送流程在 [chatSession.js](../../ray-agent-web/src/stores/chatSession.js)，HTTP 请求和 SSE 读取在 [api/chat.js](../../ray-agent-web/src/api/chat.js)。后端入口是 [ChatController.stream](../../ray-agent-server/src/main/java/cn/ray/agent/server/chat/ChatController.java)。

**主要经过：**

1. `ChatController.stream` 校验请求中的消息、会话和请求编号。
2. [ChatApplicationService.stream](../../ray-agent-server/src/main/java/cn/ray/agent/server/chat/ChatApplicationService.java) 选择模型、读取会话，检查幂等并预留容量。
3. [RunSnapshotService](../../ray-agent-server/src/main/java/cn/ray/agent/server/admin/RunSnapshotService.java) 与 [ConversationRepository](../../ray-agent-server/src/main/java/cn/ray/agent/server/conversation/ConversationRepository.java) 创建 `QUEUED` run 和配置快照。
4. [QueuedRunDispatcher](../../ray-agent-server/src/main/java/cn/ray/agent/server/run/dispatch/QueuedRunDispatcher.java) 安排运行；[ContextPreparationService](../../ray-agent-server/src/main/java/cn/ray/agent/server/chat/ContextPreparationService.java) 准备上下文，[ModeDispatcher](../../ray-agent-server/src/main/java/cn/ray/agent/server/chat/ModeDispatcher.java) 选择工作流。
5. `ChatApplicationService` 内部 `ChatRun` 消费模型片段和事件，通过 SSE 回传并处理终态；运行和事件由 `ConversationRepository` 保存。

| 模型渠道或默认模型 | [ModelChannelService](../../ray-agent-server/src/main/java/cn/ray/agent/server/model/ModelChannelService.java) |
| 请求幂等 | [RequestIdempotencyService](../../ray-agent-server/src/main/java/cn/ray/agent/server/run/admission/RequestIdempotencyService.java)、`ConversationRepository.beginQueued` |
| 流事件、心跳、断线和终态 | `ChatApplicationService.ChatRun`、前端 `api/chat.js` |
| 会话模式分派 | `ModeDispatcher.bind` |

## 02 Agent 与工具循环

**入口：** [GeneralChatWorkflow.bind](../../ray-agent-server/src/main/java/cn/ray/agent/server/chat/GeneralChatWorkflow.java) 按策略确定工具范围并绑定普通聊天 Agent；[ReactLoopAgent.bind / Loop.run](../../ray-agent-runtime/src/main/java/cn/ray/agent/runtime/agent/ReactLoopAgent.java) 组织多步模型调用。

**主要经过：**

1. `GeneralChatWorkflow` 根据是否允许联网和当前策略确定工具名单。
2. `ReactLoopAgent.bind` 绑定模型、名单、`RunBudget` 和 `AgentEventSink`；真正运行在内部 `Loop.run`。
3. [ToolRegistry](../../ray-agent-runtime/src/main/java/cn/ray/agent/runtime/tool/ToolRegistry.java) 提供允许的工具定义；[LlmAdapter](../../ray-agent-runtime/src/main/java/cn/ray/agent/runtime/model/LlmAdapter.java) 调用模型。
4. 模型请求工具时，`Loop` 检查模型步骤、工具次数和调用编号；[ToolExecutor](../../ray-agent-runtime/src/main/java/cn/ray/agent/runtime/tool/ToolExecutor.java) 检查权限、工具和参数并执行。
5. 成功或普通失败的 `ToolResult` 以工具消息回填；循环继续，直到回答、等待用户、预算耗尽、取消或错误。

## 03 文档上传与异步入库

**入口：** [DocumentUploadController.upload](../../ray-agent-server/src/main/java/cn/ray/agent/server/knowledge/DocumentUploadController.java) 接收文件；[DocumentService.upload](../../ray-agent-server/src/main/java/cn/ray/agent/server/knowledge/DocumentService.java) 校验并登记版本。

**主要经过：**

1. `DocumentService` 校验文件、计算摘要并经 [DocumentFileStore](../../ray-agent-server/src/main/java/cn/ray/agent/server/knowledge/DocumentFileStore.java) 保存原文件；`DocumentRepository.accept` 登记待处理版本。
2. [DocumentIngestionService.start / poll](../../ray-agent-server/src/main/java/cn/ray/agent/server/rag/ingest/DocumentIngestionService.java) 后台轮询，通过 `DocumentRepository.claim` 领取待处理版本；这不是上传线程同步完成入库。
3. `DocumentIngestionService.process` 读取并核对原文件，使用 [ParserSelector](../../ray-agent-server/src/main/java/cn/ray/agent/server/rag/parse/ParserSelector.java) 选择 [PdfDocumentParser](../../ray-agent-server/src/main/java/cn/ray/agent/server/rag/parse/PdfDocumentParser.java) 或 [TextDocumentParser](../../ray-agent-server/src/main/java/cn/ray/agent/server/rag/parse/TextDocumentParser.java)。
4. [DocumentChunker](../../ray-agent-server/src/main/java/cn/ray/agent/server/rag/chunk/DocumentChunker.java) 切分；`DocumentRepository.saveChunks` 保存片段；[EmbeddingClient](../../ray-agent-server/src/main/java/cn/ray/agent/server/rag/embedding/EmbeddingClient.java) 分批生成向量。
5. `DocumentRepository.publish` 在事务中检查版本、写入向量并切换有效版本。上传已接收不等于版本已经可检索。

| 想修改 / 排查 | 先看 |
| --- | --- |
| 支持格式、大小、上传校验 | `DocumentService.upload`、`ParserSelector` |
| PDF、Markdown、TXT 的解析 | `PdfDocumentParser`、`TextDocumentParser` |
| 切块长度、重叠和位置 | `DocumentChunker`、[ChunkPolicy](../../ray-agent-server/src/main/java/cn/ray/agent/server/rag/chunk/ChunkPolicy.java) |
| 向量接口和维度 | [OpenAiEmbeddingClient](../../ray-agent-server/src/main/java/cn/ray/agent/server/rag/embedding/OpenAiEmbeddingClient.java)、[EmbeddingProfile](../../ray-agent-server/src/main/java/cn/ray/agent/server/rag/embedding/EmbeddingProfile.java) |
| 发布、失败与重试 | `DocumentRepository.publish / fail`、[RetryScheduler](../../ray-agent-server/src/main/java/cn/ray/agent/server/rag/ingest/RetryScheduler.java) |

## 04 知识库检索与回答

**入口：** [KnowledgeChatWorkflow.bind / Execution.run](../../ray-agent-server/src/main/java/cn/ray/agent/server/chat/KnowledgeChatWorkflow.java)。这条 KNOWLEDGE 路径不使用网页工具。

**主要经过：**

1. 可选 [QueryRewriter](../../ray-agent-server/src/main/java/cn/ray/agent/server/rag/retrieve/QueryRewriter.java) 做受限问题补全；实验默认关闭。
2. [GroundedAnswerService.retrieve](../../ray-agent-server/src/main/java/cn/ray/agent/server/rag/answer/GroundedAnswerService.java) 调用 [RetrievalService.retrieve](../../ray-agent-server/src/main/java/cn/ray/agent/server/rag/retrieve/RetrievalService.java)，验证知识库范围，生成查询向量并搜索。
3. 默认调用 [PgVectorStore](../../ray-agent-server/src/main/java/cn/ray/agent/server/rag/store/PgVectorStore.java) 做向量检索。可选 [HybridRetriever](../../ray-agent-server/src/main/java/cn/ray/agent/server/rag/retrieve/HybridRetriever.java) 组合 [KeywordRetriever](../../ray-agent-server/src/main/java/cn/ray/agent/server/rag/retrieve/KeywordRetriever.java) 和 [RankFusion](../../ray-agent-server/src/main/java/cn/ray/agent/server/rag/retrieve/RankFusion.java)；混合实验默认关闭。
4. [EvidenceAssembler](../../ray-agent-server/src/main/java/cn/ray/agent/server/rag/answer/EvidenceAssembler.java) 与 [EvidenceBudgetPolicy](../../ray-agent-server/src/main/java/cn/ray/agent/server/rag/answer/EvidenceBudgetPolicy.java) 组装证据；无证据则拒答。可选 [Reranker](../../ray-agent-server/src/main/java/cn/ray/agent/server/rag/retrieve/Reranker.java) 对候选排序，实验默认关闭。
5. 模型先判断证据是否足够，[CitationValidator](../../ray-agent-server/src/main/java/cn/ray/agent/server/rag/answer/CitationValidator.java) 校验选择与引用；生成前后通过 `GroundedAnswerService.requireCurrent` 检查资料版本。

| 检索数量、向量与关键词融合 | `RetrievalService`、`HybridRetriever`、`KeywordRetriever`、`RankFusion` |

## 05 会话上下文与摘要

**入口：** [ContextPreparationService.bind](../../ray-agent-server/src/main/java/cn/ray/agent/server/chat/ContextPreparationService.java)，在本次工作流执行前准备上下文。

**主要经过：**

1. [SessionRebuilder](../../ray-agent-server/src/main/java/cn/ray/agent/server/conversation/SessionRebuilder.java) 从持久记录重建成功轮次；[SessionRestoreService](../../ray-agent-server/src/main/java/cn/ray/agent/server/conversation/SessionRestoreService.java) 验证已保存摘要覆盖范围并恢复投影。
2. [TokenEstimator](../../ray-agent-runtime/src/main/java/cn/ray/agent/runtime/context/TokenEstimator.java) 估算长度；达到 [CompactionPolicy](../../ray-agent-runtime/src/main/java/cn/ray/agent/runtime/context/CompactionPolicy.java) 的条件且预算允许时，尝试压缩较早轮次。
3. [CompactionEngine](../../ray-agent-runtime/src/main/java/cn/ray/agent/runtime/context/CompactionEngine.java) 构造摘要请求并检查结果；[CompactionRecorder](../../ray-agent-server/src/main/java/cn/ray/agent/server/conversation/CompactionRecorder.java) 校验范围、版本及运行状态后发布摘要。
4. [ModeContextPolicy](../../ray-agent-server/src/main/java/cn/ray/agent/server/chat/ModeContextPolicy.java) 和 [ContextAssembler](../../ray-agent-runtime/src/main/java/cn/ray/agent/runtime/context/ContextAssembler.java) 按预算选消息，再交给 `ModeDispatcher`。

| 想修改 / 排查 | 先看 |
| --- | --- |
| 摘要触发阈值、保留轮次 | `ContextPreparationService`、`CompactionPolicy`、[application.properties](../../ray-agent-server/src/main/resources/application.properties) |
| 摘要提示词及长度检查 | `CompactionEngine.request / evaluate` |
| 原历史和摘要如何恢复、避免重复 | `SessionRebuilder`、`SessionRestoreService`、`CompactionRecorder` |
| 保留哪些轮次、工具消息是否配对 | `ModeContextPolicy`、`ContextAssembler` |
| 输入长度估算 | `TokenEstimator`、[ContextAllocationPolicy](../../ray-agent-runtime/src/main/java/cn/ray/agent/runtime/context/ContextAllocationPolicy.java) |

**边界：**摘要是会话投影，原始消息不因此删除；当前估算不等于供应商真实 Token，摘要变短也不保证关键信息无遗漏。这里不是已实现的独立长期用户记忆。

## 06 运行生命周期与恢复

**入口：** [ChatApplicationService.stream / resume / cancel](../../ray-agent-server/src/main/java/cn/ray/agent/server/chat/ChatApplicationService.java)，分别对应发起、接续和取消。

**主要经过：**

1. [RequestIdempotencyService](../../ray-agent-server/src/main/java/cn/ray/agent/server/run/admission/RequestIdempotencyService.java) 检查重复请求；[BoundedRunExecutor.reserve](../../ray-agent-server/src/main/java/cn/ray/agent/server/run/admission/BoundedRunExecutor.java) 预留总容量。
2. `ConversationRepository.beginQueued` 创建 `QUEUED` 运行并检查同会话活动 run 上限（默认2，含 RUNNING/QUEUED/WAITING_USER）；`RunSnapshotService` 同事务记录运行配置。
3. [QueuedRunDispatcher](../../ray-agent-server/src/main/java/cn/ray/agent/server/run/dispatch/QueuedRunDispatcher.java) 提交给执行器；[RunQueue](../../ray-agent-server/src/main/java/cn/ray/agent/server/run/dispatch/RunQueue.java) 按 `queue_seq` 单进程 FIFO 等待，[SessionRunGate](../../ray-agent-server/src/main/java/cn/ray/agent/server/run/admission/SessionRunGate.java) 保证同一会话串行，取得执行槽后由 [TaskStateRepository](../../ray-agent-server/src/main/java/cn/ray/agent/server/run/dispatch/TaskStateRepository.java) 更新执行状态。
4. 需要用户回答时，[PendingQuestionStore](../../ray-agent-server/src/main/java/cn/ray/agent/server/run/question/PendingQuestionStore.java) 保存问题和受支持的检查点，运行进入 `WAITING_USER` 并释放执行容量。
5. [UserAnswerController](../../ray-agent-server/src/main/java/cn/ray/agent/server/run/api/UserAnswerController.java) 接收回答，`ChatApplicationService.resume` 校验并重新准入，[RunResumeService](../../ray-agent-server/src/main/java/cn/ray/agent/server/run/question/RunResumeService.java) 按原 run 检查点继续。
6. [RunStateService](../../ray-agent-server/src/main/java/cn/ray/agent/server/run/RunStateService.java) 在启动时获取单实例锁，[InterruptedRunRecovery](../../ray-agent-server/src/main/java/cn/ray/agent/server/task/InterruptedRunRecovery.java) 处理旧运行和文档任务；重启不自动整轮重放聊天。

| 想修改 / 排查 | 先看 |
| --- | --- |
| 总并发、队列容量、每 owner 限额 | `BoundedRunExecutor`、[RunConcurrencyPolicy](../../ray-agent-server/src/main/java/cn/ray/agent/server/run/admission/RunConcurrencyPolicy.java)、`RunQueue` |
| 同一会话可排队但串行执行 | `ConversationRepository.beginQueued`、[SessionRunGate](../../ray-agent-server/src/main/java/cn/ray/agent/server/run/admission/SessionRunGate.java)、[SessionWriteLease](../../ray-agent-server/src/main/java/cn/ray/agent/server/run/admission/SessionWriteLease.java) |
| 取消、超时、释放容量 | `ChatApplicationService.ChatRun`、`QueuedRunDispatcher`、`BoundedRunExecutor.Permit` |
| 提问、过期、重复回答与接续 | `PendingQuestionStore`、`UserAnswerController`、`RunResumeService` |
| 进程重启与中断处理 | `RunStateService`、`InterruptedRunRecovery`、`ConversationRepository.recover` |

**边界：**单进程内存队列不是持久化 MQ；数据库保存运行状态和事件。等待期间释放执行容量，但同会话闸门仍由该 run 持有；普通追问可排队（默认最多2条活动 run），取得闸门后才执行。每条排队消息占用一条 SSE，HTTP/1.1 同源连接数仍是后续扩展限制。检查点接续覆盖代码支持的场景，不是任意位置恢复。

**已有测试和验收资料：**[AdmissionComponentScanTest](../../ray-agent-server/src/test/java/cn/ray/agent/server/run/admission/AdmissionComponentScanTest.java)、[RunQueueTest](../../ray-agent-server/src/test/java/cn/ray/agent/server/run/RunQueueTest.java)、[PostgresTaskTest](../../ray-agent-server/src/test/java/cn/ray/agent/server/task/PostgresTaskTest.java)、[PostgresContextTest](../../ray-agent-server/src/test/java/cn/ray/agent/server/conversation/PostgresContextTest.java)、[队列与恢复验收](../../tests/acceptance/queue-and-recovery.md)。
