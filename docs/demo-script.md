# 本机演示脚本

演示前按[干净启动](operations/clean-start.md)启动，登录个人账号；真实模型与Embedding分别探测通过。资料使用`tests/fixtures/rag-cases.json`或自己写的非敏感文本，不能把用户私人课程作为公开演示资料。

1. **CHAT**：新建CHAT会话问普通问题，再要求搜索官方文档。观察网页工具与W引用；资料库内容不应进入这条路径。没有Tavily配置时明确展示限制，不冒充联网成功。
2. **KNOWLEDGE**：上传自写资料，等版本READY后新建KNOWLEDGE会话；问资料里的事实，点击K引用看文档版本/页段。再问资料没有的事实，观察依据不足且没有网页工具。
3. **AUTO**：选授权知识库，请求比较资料与最新公开信息，观察路由及K/W分栏；歧义问题按原run补充，不能把补充当新会话请求。
4. **运行治理**：显示sessionId/runId/clientRequestId各自用途；取消一个自己的运行，刷新看持久终态。排队/429用隔离的`tools/verify_r11.py`，不要在真实供应商上压测。
5. **管理**：改默认模型或策略后发新请求；再看旧run快照保持原值。向量空间切换需要没有活动任务，旧索引明确重建。
6. **实验**：展示检索对照报告中的改善和退化；说明默认仍是向量基线。打开实验仅在隔离实例，展示重排编号校验与失败回退，不把重排通过等同于回答正确。

演示记录应包含Git提交、日期、模型配置名、向量维度、资料规模与是否模拟。当前未验证的部署、外部供应商故障或本人理解不能靠演示文案补齐；事实见[质量报告](../tests/evaluation/quality-report.md)和[贡献对账](resume-claims.md)。

## 沿用R06～R08的具体输入

先上传自写文本：`内部巡检计划代号是 R6Mango91。项目建议使用Java17。这是历史方案，不代表目前最新发布。`，等待READY。

| 模式/操作 | 输入或动作 | 观察点 |
| --- | --- | --- |
| CHAT | 我的资料中的巡检计划代号是什么？ | 不读KB，轨迹无RAG检索事件 |
| KNOWLEDGE | 所选资料中的巡检代号是什么？ | R6Mango91及K引用，可打开原文 |
| KNOWLEDGE | 资料没写的今天的天气，请联网补充 | 明确依据不足，没有网页工具 |
| AUTO | 你好；我的资料中的巡检计划代号是什么？ | 分别观察DIRECT与KNOWLEDGE路由 |
| AUTO | 比较我的资料推荐的Java版本与网上最新Java长期支持版本，分别标明来源 | HYBRID、K/W分别标来源；抓取失败与搜索摘要分开 |
| 资料生命周期 | 刷新，再重建/删除该文档 | 模式与路由恢复，旧K引用失效，不能扩大资料范围 |
| CHAT提问接续 | 请单独调用ask_user问我目标城市，等我回答后再写一句欢迎语 | WAITING_USER、等待工具卡，刷新仍可见 |
| 补充 | 苏州 | 原runId继续，仅一个最终助手结果；取消后不再接续 |

摘要实验使用`python tools/verify_r07.py --live --browser`，只在隔离环境降低阈值，不更改正式会话的策略。容量/重试演示使用`python tools/verify_r08.py --browser`；真实接口复验可加`--live`。先确认自己的本机Embedding配置，缺少配置时不能把跳过的入库记为通过。

任务页看执行中/QUEUED及槽位，默认2执行/8排队；同会话活动请求409不能当成跨会话压测。取消队列项不调用模型，临时文档错误有有限尝试，重启旧运行中断而不整轮重放。R06～R08主链路仍可从ChatApplicationService → ModeDispatcher → AutoChatWorkflow/IntentRouter → 目标workflow继续带读；新增源码未读不记为掌握。
