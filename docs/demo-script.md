# 三模式本机演示脚本

2026-10-30。需要本机数据库、模型、Embedding配置可用，网页搜索需Tavily。IDEA运行服务端main，工作目录设为工程根；前端执行 `npm run dev`。本节没有部署，登录尚未实现。

1. 在知识库管理创建“演示资料”，上传自己编写的Markdown：`内部巡检计划代号是 R6Mango91。项目建议使用Java17。这是历史方案，不代表目前最新发布。`，等待READY。
2. 新建CHAT，问“我的资料中的巡检计划代号是什么？”：不能读取知识库。查看运行记录不应有RAG事件。
3. 新建KNOWLEDGE并勾选演示资料，问“所选资料中的巡检代号是什么？”：预期R6Mango91和K引用，点击打开原文。
4. KNOWLEDGE内问未涉及的问题并要求联网：应说明资料依据不足，没有网页工具调用。
5. 新建AUTO并勾选资料，先问“你好”：路由为直接对话；再问“我的资料中的巡检计划代号是什么？”：路由知识库，带K引用。
6. AUTO问“比较我的资料推荐的Java版本与网上最新Java长期支持版本，分别标明来源”：预期HYBRID轨迹、两个来源栏目和比较局限；K打开当前资料，W打开本次实际网页。
7. 网页抓取若403或超时，展示失败卡与回答限制；不要把搜索摘要说成已抓取的全文。若两类内容冲突，应分别展示而非擅自选一个当事实。
8. 刷新确认路由和来源恢复；仅切“新会话模式”不影响当前会话，再点击新建才会切换。
9. 删除/重建资料后旧K引用失效；AUTO空范围资料问题要求先选择知识库。历史范围不能由模型擅自扩展。

读代码的接续位置：ChatApplicationService → ModeDispatcher → AutoChatWorkflow → IntentRouter/RoutePolicy → HybridChatWorkflow → SourceAttributionPolicy。开发与验证由助手完成，用户尚未带读，不能直接记为本人已掌握或独立实现。

## R08补充演示

- 使用不同会话连续提交较慢的请求，顶部“任务与运行”区分执行中与QUEUED，显示当前槽位/队列容量；超载429提示等待。默认2执行/8排队，别把同会话双击提交当跨会话并发。
- 取消QUEUED运行，状态为CANCELLED，不出现模型/工具执行；点击“查看会话”回到原记录。已有活动运行的同会话新问题409，重复请求通过原clientRequestId查run。
- 文档临时失败后查看每次尝试、阶段与错误码；永久错误不反复重试，最新失败版本可手动重试。请在隔离脚本中注入503，不修改真实供应商服务。
- 用`python tools/verify_r08.py --browser`在隔离环境演示容量、取消、文档重试及强杀恢复；真实聊天加`--live --skip-embedding`。本机Embedding key已删除，完整真实文档复验需先由用户恢复配置。
- 重启后的旧运行显示INTERRUPTED，不能点按钮假装从任意位置继续。WAITING_USER有有效检查点才允许补充，接续仍是原run；更多见`tests/acceptance/queue-and-recovery.md`。R07/R08代码尚未学习，不记为已掌握。
