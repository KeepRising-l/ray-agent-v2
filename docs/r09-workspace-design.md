# R09 工作区设计与交互依据

2026-10-31。目标：在当前会话里完成提问、核对来源和处理异常，随时知道正在查看哪次运行。

首版用户仍是个人账号使用者。桌面为主要设备，补查390px窄屏和200%放大；数据由现有会话、知识库和任务接口提供，不新增业务接口或依赖。复用白底、系统字体、原有按钮和组件，发送作为主要动作。

## 结构

桌面顶部保留聊天、知识库管理、任务与运行三个入口。聊天左侧放会话切换和新会话设置，右侧放服务端确认的标题、模式、资料范围、历史、补充问题与输入。来源和运行诊断跟在回答后；事件与编号默认折叠。手机改为单列，有会话时默认收起新建表单，优先看到当前对话。

```text
RayAgent V2                     聊天  知识库管理  任务与运行
会话选择       | 当前会话标题 / 模式 / 所选资料
新建设置       | 历史消息与引用入口
               | 补充问题 / 消息输入 / 发送与运行操作
               | 原文 / 网页来源 / 折叠的事件与用量
```

去掉了App里的业务状态和重复诊断展开，保留主流程可见反馈；运行事件改为短文案，编号收进折叠区。素材由真实文字、资料片段和运行事件构成，无新增配图、图标库或外部字体。

## 状态与边界

- 服务端决定会话模式、知识库范围、历史和运行终态。左栏的新模式只影响新建会话。
- 会话、轨迹、文档版本和引用读取分别防止迟到响应覆盖新选择；本地SSE按原session归属，切换会话不会移交文本或事件。普通草稿仅在当前页面按会话暂存。
- 未确认的聊天请求保留原clientRequestId与输入到本机浏览器存储，刷新后只提示查询；查到原run就查看它，404后的相同输入重发沿用原编号。没有自动重订阅或自动整轮重跑。
- WAITING_USER继续使用原run/question；取消后以服务端状态为准。模型失败保留部分回答，编辑操作只回填问题，发送才创建新运行。文档失败的操作仍是该文档最新版本的重试。
- 原文每次打开都由服务端校验。正文K/W标记绑定所属回答的run，K展开原文，W定位已有工具来源；运行输出期间与轨迹选择一起暂时锁定来源切换。
- 本地估算和供应商usage分别显示，null为未知/未提供。浏览器刷新后查询持久事件，不声称无损接回token流。

动作反馈为按钮按下的短位移、首次工作区淡入，以及消息入场；均在160ms内，并遵循减少动态效果设置。没有持续装饰动画。解析/分块/向量状态来自接口，不模拟百分比。
