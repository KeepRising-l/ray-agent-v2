# 运行与资料恢复手册

先在原会话或后台查runId、clientRequestId、文档版本及尝试记录。记录状态和失败码，不复制密钥、网页正文、完整模型上下文或密码到公开Issue。

| 现象 | 先确认什么 | 可执行的恢复 | 不能据此声称 |
| --- | --- | --- | --- |
| 登录失效/写请求403 | 刷新登录状态；确认会话是否过期 | 重新登录后先查询原请求，明确是否需要再次操作 | 不能自动重放写操作 |
| 模型401/配置缺失 | 后台渠道是否启用、密钥是否配置、Base URL/模型是否正确 | 本机更新密钥并检查；失败聊天编辑后显式新发 | 不自动整轮重跑 |
| 上游临时503 | 模型协议重试与文档处理重试是不同层 | 看真实失败码和尝试记录，按允许范围有限重试 | 部分文本输出后不能盲目重试 |
| 浏览器断开/请求结果未知 | 用原clientRequestId查询是否已有run | 恢复历史、状态与事件；需要时明确取消 | 刷新不是SSE断点续传 |
| 队列满429 | 后台执行槽/队列容量，当前是否还有活动任务 | 等待或取消不再需要的任务 | 429没有创建run，不计为模型成功请求 |
| 服务进程异常结束 | QUEUED/RUNNING是否变为INTERRUPTED | 文档按最新版本明确重试，聊天重新发问 | 内存队列不是持久调度队列 |
| WAITING_USER | 原question是否仍有效，快照是否兼容 | 在原会话补充，仍用原run/question；配置不兼容则取消重问 | 不支持任意工具步骤恢复 |
| Embedding401 | 本机向量密钥与实际向量模型 | 更新凭据后重试同一目标空间的最新失败版本 | 认证失败不应自动反复消耗重试 |
| 向量空间变化 | 当前profile、模型、维度、版本与已发布索引是否一致 | 停止活动处理后改配置，再逐文档明确重建 | 旧READY不代表能用于新空间 |
| 新版本入库失败 | 上一有效版本与当前处理版本分开看 | 修复文件/配置，重试最新失败版本 | 不把上传成功记为可检索 |
| 后台补偿REQUESTED/INTERRUPTED | 操作编号、目标和实际文档/运行结果 | 同编号先查；结果确认后才发一个新的明确操作 | 不能承诺跨外部调用exactly-once |
| 重排格式错误或临时失败 | RAG_RERANK_FALLBACK；是否还有预算/时限 | 沿用原候选与判断流程，必要时关闭实验后重启 | 回退不等于这次重排有收益 |
| 关键词查询失败 | 固定日志RAG_KEYWORD_FALLBACK与基线状态 | 只回退同范围、同查询向量的基线 | 不转查别人的库或联网 |

R11实验参数为`ray.rag.experimental.hybrid/rewrite/rerank`，默认false，修改后重启。快照保留原值；等待中的旧运行若与当前策略不同，接续返回409且不消费问题。查询改写仅拼接最近的用户问题，助手历史不作为当前事实；当前实现不是任意语义模型改写。

服务健康通过不代表外部服务正常。先检查`/api/health`与数据库，再在后台分别检查模型、Embedding；外部检查可能产生用量。数据库不可用时不能相信内存中的成功提示；恢复连接后查持久状态。

升级/备份：停止app后备份数据库、原文及本机身份/密钥，记录当前Git提交和镜像ID；然后按[干净启动说明](clean-start.md)更新。旧版本回退需要验证SQL/快照兼容，必要时恢复成套备份，不单独替换一个文件。不输出完整Compose配置，因为它可能包含环境密码；校验使用`config --quiet`。
